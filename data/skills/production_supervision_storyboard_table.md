# 分镜表监督审核

只审核指令指定或当前正式提交的同一 `generationId/revision`。剧本、导演规划和资产是上游依据；旧版本只用于有明确基线的返修对照。

## 证据要求

每个问题必须包含正式 storyboard index、当前字段名、当前字段真实原文、上游依据、影响、归属和修复方向。当前目标字段没有直接证据时不得提交；上游自身错误应标记上游归属，不能重复算作本 Revision 的创作错误。

轻微措辞偏好、可选机位留空、普通硬切未写转场不阻断下一阶段。

## 单轮四遍

前三遍只记录内部进度，不保存报告或提前等待用户：

1. **事实与范围**：读取正式 V3 行、剧本、导演规划、资产和上一轮完整问题，确认审核对象与版本。
2. **全局检查**：检查事件、台词、因果顺序、镜头切分、分组、整体时长和场间状态。
3. **专业逐镜检查**：从第一镜到最后一镜检查所有正式字段、动作可执行性、声音、资产和相邻连续，不抽样。
4. **漏检复查与归并**：从剧本事件、关键台词、资产和每个 group 反查遗漏；再次读取准备引用的字段原文，删除没有证据的问题。

前三遍不得保存报告或提前结束。第四遍完成前不得输出“审核完成”。同一根因影响多个位置时合并为一项并列出全部受影响位置。返修后的审核仍执行完整四遍。

## V3 专业检查

### `shotDescription`

- 是否按“最早可见状态 → 触发 → 连续变化 → 结束状态”自然展开；
- 起点是否来自明确事实、首动作必然前态或相邻正式镜头的明确交接；
- 是否借“必然前态”补写了精确站位、方向、布局、未出现物件、后续人物或动作结果；
- 主体、对象、接触和可见结果是否清楚，是否出现两个互相竞争的主要行动；
- 结束状态是否保留下一镜真正需要的连续信息。

### 关键可见表演

当剧本或导演规划明确人物接收信息、关系位移、判断、克制、犹豫、态度翻转或情绪转折，而该反应本身是本镜新增信息时，检查 `shotDescription` 是否有对应的可见证据：触发后的视线、面部、呼吸、手部或姿态变化及其结束状态。只写“愤怒”“紧张”等抽象词，或只剩普通动作/台词而没有可见反应，可报告“缺少可见表演证据”。

普通对白、静态说明或上游没有明确反应依据时，不要求补微表情；不得恢复独立情绪字段或人物表演数组。

### 镜头切分质量

逐项识别以下明确问题：

- 同一连续动作在相邻镜头中重复发生，后一镜依靠重做前一镜动作才能成立；
- 一个镜头包含多个独立视觉中心、不同信息接收者或无法连续完成的因果目标；
- 新信息依赖于屏幕、纸张、照片、镜面、仪表或远端画面等可读视觉载体，同时又要求读清另一人物的独立反应或行动，且同一构图无法自然承载两者；
- 切点落在不能自然中断的抓取、递交、起身、转身、进出或其他动作中段；
- 相邻镜头只机械更换景别，没有新增事实、判断、关系或状态；
- 对话始终停留在说话者，遗漏确有叙事作用的听者反应或台词指向物；
- 插入镜没有提供新信息，只是装饰画面；
- 为填满视频模型最大时长而合并本应独立的行动，或分组在没有自然切点处结束。

不要因为个人偏好要求更多镜头。只有能指出缺失信息、重复动作、错误切点或不可连续执行的具体证据时才报告。

### 景别、时长与连续性

- `shotSize` 是否能清楚呈现本镜真正新增的空间、动作、判断或物件状态；连续中景是否都有实际信息理由；
- 若关键可见表演是本镜不可替代的新信息，当前景别和时长是否足以看清；若与完整动作不能兼容，是否应以有证据的自然切点拆开，而非同时堆入一镜；
- 台词、必要停顿、反应和动作是否明显无法在 `durationSec` 内完成；边缘性的节奏偏好不报阻断；
- 相邻静场是否都提供新增事实、动作结果、必要反应或空间/声音交接；若只是重复停顿，只有能列出相邻镜证据时才报告合并或缩短建议；
- 画外续说的说话者、原文片段和顺序是否连续、无重复；
- 当前结束状态与下一镜起点是否承接，人物、物件、门窗、屏幕、车辆、伤病、服装和持续声音是否无因跳变；
- `cameraAngle` 只有在方向或剪辑连续确有需要时检查；真实跨侧应有移动、沿轴/中性镜头或重新建立空间的依据。

### 台词、声音与资产

- 台词忠实剧本且顺序正确；`voiceTone` 不改写台词事实；
- `soundEffects` 有画内来源并按发生顺序，不把 BGM 当现场声；
- 本镜可辨识人物、场景和关键道具在 `requiredAssets` 中有合法项目内 ID；
- 资产稳定外形没有在 `shotDescription` 中冗长重复或被无依据改写。

V3 不审核 `picture`、`action`、`visibleEmotion`、`characters[]`、行级 `groupName/groupIntent`，也不得要求恢复它们。

## 最终报告结构

有明确前后版本时按 `已修复 / 仍存在 / 返修回归 / 历史漏检` 分类；不得从报告措辞猜测返修前 generation/revision，不能只因上一轮没写就默认归历史漏检，原版没有而本轮修改区域出现的问题才可归返修回归。无明确基线时新问题统一为“新发现（基线不可判定）”。只列异常，不罗列通过项。第四遍再次读取目标原文确认逐字证据仍存在，完成后只调用一次 `record_storyboard_table_review`，不得分批保存；逐镜项使用正式 `storyboardIndex`，不猜业务 ID。
