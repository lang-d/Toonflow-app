# 分镜图 Prompt 通用技法

本技能只处理“画面是否成立”和“Prompt 是否可用于单张分镜图”。它不决定画风，也不新增剧情事实。画风、媒介、渲染方式、笔触、材质和色彩体系只能来自 `scriptPlan` 明确写出的视觉方案、`tableRowJson` 事实或参考资产；不得根据 `artStyle` 名、视觉手册名、导演手册名或题材名自行补风格。

## 信息来源

1. `tableRowJson` 是当前镜头事实的唯一来源：人物、动作、位置、朝向、构图、场景、道具、可见情绪都以它为准。
2. `assets` 只提供角色外观、场景结构、道具外观和可用参考图；不得从资产描述里新增本镜头没有出现的动作、关系或剧情。
3. `scriptPlan` 只提供短视觉原则和已确定的场景视觉状态；不得用它补写逐镜动作、机位或心理解释。
4. `scriptPlan` 和参考资产只决定“怎么表现”，不能改变 `tableRowJson` 里的“拍什么”。

低优先级内容不得覆盖高优先级事实。`dialogue` 和 `soundEffects` 不直接进入图片 Prompt，除非它们已经在结构化视觉字段中转化为可见动作、物件或状态。

## 编译流程

先按 `sceneContinuityId` 和 `index` 建立场景连续性 ledger，再逐条编译 Prompt。不得把同一场景连续镜头当成彼此无关的独立图片。

场景连续性 ledger 必须追踪：

- 分镜表已经确定的轴线、机位组、轴线侧、人物视角和镜头朝向。
- 当前应使用的父场景或场景角度衍生资产，以及该参考图能约束的空间范围。
- 每个角色的真实站位、画面位置、前中后景、站坐、身体朝向、脸部朝向、视线、遮挡和可见身体范围。
- 核心道具的位置、所有权、正反面、开合/亮屏/损坏等当前状态。
- 上一镜终态、当前镜定格点和下一镜需要承接的连续性事实。
- 导演规划或参考资产已经确定的主光方向、时间、天气和场景状态。

每条 Prompt 必须先完成内部判断，再输出最终文本：

1. 从 `cameraAngle` 读取标准机位签名，不重新选择轴线或机位。
2. 建立内部画框硬约束。
3. 把真实站位转换成当前机位下的画面左右、前后景和遮挡关系。
4. 做单机位可见性裁剪。
5. 从动作链中选择一个画面锚点。
6. 将表演和情绪转成当前可见物理状态。
7. 为每张参考资产确定用途和优先级。
8. 按固定句式输出最终 Prompt。

内部帧规格只用于推理和裁剪，不得输出到最终 Prompt，也不得写入数据库。

内部帧规格必须包含：

- 机位签名：轴线、机位组、轴线侧、人物视角和镜头朝向；最终 Prompt 转成可拍视角，不输出只有内部系统能理解的孤立代号。
- 场景视角：当前场景参考图是否与机位签名、时间、天气和空间状态匹配。
- 镜头视点：正面、背面、侧面、斜前、斜后、俯视或仰视。
- 主体朝向：每个可见主体面向镜头、背向镜头、侧面对镜头，或面向其他角色/物件。
- 画面坐标：每个主体位于画面左侧、中央或右侧，以及前景、中景或背景。
- 姿态与裁切：站立、坐着、蹲下、倚靠或俯身；全身、半身、肩背、手部或其他可见范围。
- 遮挡关系：前景人物、门框、桌面、道具等遮挡谁、遮挡到什么范围。
- 可读物件朝向：屏幕、纸张、书信、票据、牌匾、碑文、卷轴、仪表盘、照片等正反面是否朝向镜头。
- 可读文字：哪些文字在当前机位可读；不可读则舍弃具体内容。
- 参考资产用途：身份、当前服装/状态、手部/袖口、场景几何、光线、道具外观或文字版式。
- 保留事实：当前机位能看见且同一时刻成立的事实。
- 舍弃事实：需要另一个机位、属于动作过程、属于心理判断或不可见的事实。

最终 Prompt 只能使用“保留事实”。不得解释舍弃原因，不得把“舍弃事实”换一种说法写回 Prompt。

## 字段映射

| 结构字段 | Prompt 处理 |
|---|---|
| `picture` | 画面主体，保留所有可见元素和空间关系。 |
| `location` | 环境锚点，结合参考图和当前画风表达。 |
| `shotSize` | 转成景别构图；复合景别取首帧起始景别。 |
| `cameraAngle` | 转成视角；无明确值时不强行添加。 |
| `action` | 识别画面关系，只保留一个可见静态状态。 |
| `characters[].action` | 提取姿态、手部状态和交互关系，不保留完整动作链。 |
| `characters[].orientation` | 明确写入角色朝向。 |
| `characters[].spatialPosition` | 明确写入角色画面位置。 |
| `characters[].posture` | 作为站立、坐着、蹲下、倚靠、俯身等硬约束，不得省略或改写。 |
| `characters[].gaze` | 明确写入当前视线对象，不写心理判断。 |
| `characters[].handAction` | 只保留当前手部终态、接触点和物件所有权。 |
| `visibleEmotion` | 转成可见表情、视线、姿态、呼吸或手部状态。 |
| `requiredAssets` | 提供语义资产需求；结合 assets、机位签名和可见范围解析实际参考用途与 `associateAssetsIds` 顺序。 |

## 硬事实与阻断

以下内容属于图片编译硬事实，不得为了让 Prompt 看似顺畅而删除、反转或自行补写：

- 主体及当前可辨识人物。
- `shotSize`、`cameraAngle` 中已经确定的机位视角。
- 角色站坐、身体朝向、脸部朝向、画面位置、前后景和遮挡关系。
- 当前镜头的核心动作定格点、手部接触关系和道具所有权。
- 承担本镜头叙事功能的核心道具、场景状态和明确要求可读的关键文字。

声音、动作次数、前史、后续结果、心理解释、象征意义和评论式构图结论属于软信息，不能进入图片 Prompt。

出现以下任一情况时，必须输出保守的单帧 Prompt，并将该分镜写为 `shouldGenerateImage: false`，同时向用户报告分镜 ID/index 和原因：

- 两个硬事实需要不同机位才能成立。
- 分镜表机位签名与所有可用场景参考图的几何方向冲突。
- 关键人物状态、场景角度或核心道具状态缺少可用资产，且仅靠文字无法可靠保持连续性。
- 同时要求人物正脸细微表演和完整可读物件，裁剪任一项都会改变镜头叙事功能。

阻断不授权本阶段修改分镜表、创建衍生资产或重新规划机位。

## 单机位可见性

生成 Prompt 前必须先判断：

1. 镜头在主体正面、背面、侧面、斜前还是斜后。
2. 主体面向镜头、背向镜头、侧面对镜头，或面向其他角色/物件。
3. 有正反面的物件，其可读面朝向哪里。
4. 哪些内容能被同一张静态图片同时看见。

如果两个事实需要不同机位才能看见，不能写进同一条 Prompt。必须选择当前镜头最核心的可见事实。

看不到的内容直接删除，不写“不再、没有、无法看见、未显示”等解释性否定句。

禁止的双机位冲突：

- 角色正面看向镜头，同时屏幕、纸张、书信、票据、牌匾或碑文内容清晰可读。
- 角色背对镜头，同时写正面表情或眼神细节。
- 远景人物全身，同时写清手中道具文字特写。
- 角色看向窗外、远方或背向镜头，同时写正脸细微表情。
- 角色转身离开，同时写正面眼神特写。

可成立写法：

- 要看角色脸：可读物件只写“握在手中”“放在桌上”“亮着”“摊开着”，不写具体文字。
- 要看物件内容：镜头改为物件可读面朝向镜头，角色只露出侧脸、背影、手部或肩背。
- 要同时看脸和物件：必须明确角色侧身、物件斜向镜头、内容只局部可见。

## 单张静态画面

分镜图是一个静态画面参考，不是动作摘要。

- 静态性高于动作语义完整性。
- 当完整动作无法在同一时刻成立时，必须舍弃过程、次数、前史和后续结果。
- 连续动作先选择一个“画面锚点状态”，再围绕该状态描述画面。
- 画面锚点优先选择最能表达人物关系、核心道具交互或剧情意图的可见瞬间。
- 镜头运动只取起始景别和起始构图。
- 转场只保留开场状态，不生成完整转场过程。
- 一条 Prompt 只能存在一个时间状态，不能同时描述动作的开始、过程和结果。
- 破折号、分号或句号不能用于串联多个先后状态；分句后的所有事实也必须能在同一时刻成立。

画面锚点按镜头功能选择：

- 证据/文字镜头：物件已经稳定、可读面朝向当前机位；人物最多保留手部、肩背或侧脸。
- 人物反应镜头：保留反应后的当前表情、姿态、视线和手部状态；不写“从……变为……”。
- 递交/争夺镜头：选择接触点或所有权已经明确的终态，只能二选一。
- 放下/收回镜头：优先选择物件已经落位、手仍停在边缘的状态。
- 进入/离开镜头：选择门槛内、门槛处或门槛外一个状态，不描述完整移动路径。
- 转场镜头：只保留新镜头的开场状态。

时间或过程表达必须改写为当前静态状态：

- `正在发消息` -> `拇指停在屏幕上方`
- `即将拐过巷口` -> `车头朝向巷口拐角`
- `越来越小` -> `主体位于远处通道中段`
- `走过来递给对方` -> `手臂伸向对方，物件停在两人之间`
- `结束通讯并收起物件` -> `通讯物件握在手中，手停在收纳位置外侧`

## 动态交互冻结

- “递来、接过、放下、转身、走出、走入、靠近、离开”等动态动词必须改写为当前可见的空间和姿态。
- “某人递来物件”可冻结为“某人手持物件，手臂从画面一侧伸向另一人”。
- “某人没有接”必须改写为可见状态，例如“双手垂在身侧”或“手停在桌沿”。
- “拿起可读物件查看内容”只能选择一个瞬间，例如“物件握在手中，视线落向物件”或“物件可读面朝向镜头，角色侧脸可见”。
- “打开、输入、发送、收起、转身离开”等动作链不得完整保留；每条 Prompt 只保留一个静态状态。
- 人物姿态与背景物件状态可以并列，但必须能被同一张图片同时拍到。

反例：

```text
角色A接过信件又低头读完，随后把信放回桌上，意识到事情不对。
```

正例：

```text
角色A位于画面左侧中景，身体面向桌面，右手停在摊开的信件边缘，视线落在信纸上；角色B位于画面右侧背景，侧身看向角色A。
```

## 可读物件与文字

- 只有 `tableRowJson` 明确写出屏幕、纸张、牌匾、票据、碑文、卷轴、仪表盘等内容，且当前机位能看见其正面时，Prompt 才能写具体文字内容。
- 如果物件正面没有朝向镜头，或被人物身体遮挡，只能写“亮着”“摊开着”“放在桌上”“握在手中”，不能写可读内容。
- 如果画面重点是人物正脸，可读物件通常不能同时清晰可读。
- 如果必须表现具体文字内容，应优先成为单独的物件特写分镜；阶段5不得把它塞进人物正面镜头。
- 不得自行生成结构化分镜没有明确提供的文字内容。

## 参考资产

- 采用“最小充分引用”，不设置脱离画面需求的简单数量上限，也不得机械复制全部 `requiredAssets`。
- P0 参考：匹配机位的场景角度、核心人物、叙事关键道具；必须保留。
- P1 参考：画面可辨识的手、袖口、肩背、前景人物、当前服装或状态；只要承担身份/连续性约束就必须保留。
- P2 参考：只提供完全虚化背景纹理、弱环境信息或不影响身份/空间/光线的辅助资产；达到模型上限或与 P0/P1 竞争时优先删除。
- 纯物件特写只有在背景几何、桌面材质或主光方向可辨识时才保留场景参考；若场景仍能被识别或决定空间方向，不得因背景虚化而删除。
- 手部特写应选择最能约束操作者身份、当前服装、袖口和工作状态的角色/服装资产；面容资产不能替代未被参考图覆盖的泥渍、伤口、戒指等当前状态。
- 泥渍、伤口、雨水、哭后妆容等临时状态必须来自 `tableRowJson` 或匹配衍生资产，不得从父资产描述推测。
- 场景参考必须匹配 `cameraAngle` 机位签名。`requiredAssets` 已提供匹配衍生时必须使用衍生；若仍是父资产，只允许选用 `scriptPlan` 明确指定、同父资产且与当前机位/状态匹配的已有衍生资产。
- 无匹配衍生时，仅在父场景几何不冲突的情况下回退父资产；不得假设图片模型能从主视图反推反向空间。
- 按最终实际使用参考的优先级和 `requiredAssets.order` 建立 `associateAssetsIds`，从 `@Image1` 开始连续编号。
- `@ImageN` 必须对应 `associateAssetsIds[N - 1]`；编号、数量和顺序必须完全一致。
- Prompt 开头统一写成“参考资产与用途：@Image1 锁定角色A身份与当前服装；@Image2 锁定场景B侧面空间和主光方向。”
- 正文涉及角色、场景和道具时，可使用名称或对应 `@ImageN` 消除歧义。
- 每个被引用资产必须有唯一编号，不遗漏、不重复、不跳号。
- 用途说明只能描述该资产实际提供的身份、状态、手部/服装、几何、光线、外观或文字版式；禁止把位置、构图或剧情解释伪装成资产内容。
- 禁止虚构不存在的 `@ImageN` 或资产 ID。
- 衍生资产使用自身名称和类型，不要回退成父资产名称。

## 人物与空间关系

- 当前画面可见人物都必须进入 Prompt，不得因其处于背景而遗漏。
- 明确人物位于画面左侧、右侧或中央，以及前景、中景或背景。
- 明确人物以正面、背面或侧面朝向镜头，并写清身体面向方向。
- 明确人物视线方向、当前姿态和与画面有关的手部状态。
- 多人物画面必须写清人物之间的左右、前后、遮挡和面对关系。
- `posture` 中的站立、坐着、蹲下、倚靠或俯身是硬约束；不得只写“位于桌边”而丢失站坐。
- 必须区分真实站位与当前机位下的画面坐标；换机位后按 `cameraAngle` 转换画面左右，不得把世界左右直接复制为画面左右。
- 身体朝向、脸部朝向和视线对象分别表达；不得用“面向某人”同时替代三者。
- 明确角色可见范围，例如全身、半身、肩背、手部或前景虚化轮廓，避免参考图把不应入画的正脸强行带入。
- 如果结构化字段只给出粗略空间位置，应结合 `picture` 中已有空间关系表达，不得凭空发明精确站位。

## 可见状态

- `visibleEmotion` 只转换成肉眼可见的表情、视线、姿态、呼吸或手部状态。
- 禁止写“代表、体现、说明、意味着、象征、仿佛、内心、意识到、理解、读取信息、形成反差、被戳中、回到节奏、在撒谎、扛住了”等心理解释和叙事判断。
- 禁止写“从...到...”这类情绪变化过程；必须选择当前一刻的可见状态。
- 抽象描述没有可见依据时直接省略，不自行创造表演细节。
- 氛围必须落实为结构化事实或参考图中已存在的光线、色彩、天气、空间状态；禁止使用空泛情绪氛围词替代画面事实。
- 禁止“压力释放、视觉句号、沉默对照、被证实、形成对抗、维持体面”等导演评论；只保留对应的肩线、手势、视线、物件位置或光线事实。

## 稳定外观边界

- 已引用人物或状态资产时，不复述年龄、脸型、固定发型、完整服装、身材设定和基础气质。
- 允许保留当前画框实际可见且影响身份、构图或光线的局部事实，例如袖口颜色、手部工作痕迹、被雨打湿的发梢、前景肩背轮廓。
- 已引用场景资产时，不复述完整装修和常态陈设；只写当前机位可见的门窗、桌面、光线入口和必要空间层次。
- 已引用道具资产时，不复述完整基础设定；只写当前朝向、位置、开合、亮屏、损坏、污染或与人物的接触关系。

## 画风边界

- 本技能不主动添加任何风格锚词、画质词、媒介词或负向词。
- `scriptPlan` 或参考资产明确体现的风格锚点可以保留，例如 2D、3D、黏土、国风赛博、真人写实、水彩、手绘等。
- 不自行读取或复制视觉手册里的固定模板、英文示例、负向词块或示例剧情。
- 不根据 `artStyle` 名、视觉手册名、导演手册名或题材名推导媒介、光线、色彩、材质或画质词。
- 不用通用规则否定 `scriptPlan` 或参考资产已经确定的合法视觉表现。
- 视觉风格段最多一句，必须服务当前画面，不得挤掉具体画面事实。

## 输出语言与结构

- 除 `@ImageN` 外全部使用中文，不附加英文翻译、XML、Markdown 或负向词块。
- 使用紧凑三段式纯文本：
  1. `参考资产与用途：` 按顺序列出实际使用的 `@ImageN` 及其唯一用途；无参考图时省略。
  2. `静态画面：` 按“机位/景别 -> 主体位置与朝向 -> 姿态/手部/视线 -> 可见道具/背景”的顺序写。
  3. `视觉原则：` 只写 `scriptPlan` 或参考资产已确定的媒介、色彩、光线原则，最多一句；不得写镜头意义、情绪解释或构图评论，没有明确原则时省略。
- 画面段优先级最高，风格描述不得覆盖、替换或挤掉具体画面事实。
- 画面段使用短句并列，不写长句叙事；每个分句只承载一个可见事实。

通用示例：

```text
参考资产与用途：@Image1 锁定角色A身份与当前服装；@Image2 锁定场景B侧面空间与主光方向；@Image3 锁定道具C外观。
静态画面：中景。角色A位于画面左侧中景，侧身面向画面右侧的桌面，右手停在道具C边缘，视线落在道具C上；场景B位于背景，桌面与门口形成前后层次。
视觉原则：遵循 scriptPlan 已确定的短视觉原则。
```

## 自检清单

生成每条 Prompt 后逐项自检：

- `picture` 中所有可见主体、物件和空间层次是否保留。
- `location` 是否与结构化字段一致。
- `shotSize` 是否匹配。
- 是否忠实继承 `cameraAngle` 机位签名，且没有重新选择轴线或机位。
- 场景参考图是否匹配机位、时间、天气和空间状态。
- 是否选择了单一画面锚点。
- 是否只把内部帧规格中的“保留事实”写入最终 Prompt。
- 是否完成单机位可见性检查。
- 角色朝向是否来自结构化字段或 `picture` 的明确事实。
- 角色位置是否来自结构化字段或 `picture` 的明确事实。
- 站坐、真实站位、画面坐标、身体朝向、脸部朝向、视线、遮挡和可见范围是否完整保留。
- `visibleEmotion` 是否转成可见表演，而非抽象词。
- 是否引入了结构化分镜没有的角色、道具、剧情、场景状态或动作。
- 是否遗漏了 `requiredAssets` 中画面可见的资产。
- 是否把动作链压缩成单一静态状态。
- 是否删除了动作次数、前史、完成态和后续结果。
- 所有分句中的人物姿态与物件状态是否能在同一时刻成立。
- 是否存在“正脸+可读文字”“背影+正脸表情”“远景+文字特写”等双机位冲突。
- 是否把声音、BGM、运镜过程或视频提示词写进图片 Prompt。
- `@ImageN` 是否与 `associateAssetsIds` 数量、顺序完全一致。
- 每张参考图是否有唯一、真实、必要的用途；P0/P1 是否遗漏，P2 是否造成无关竞争。
- 是否出现心理解释、时间推进词、声音内容、否定解释句或评论式构图结论。
- 是否出现“正在、刚、随后、逐渐、从...到...、越来越、最终、又、继续”等过程词，或“体现、象征、意味着、压力释放、视觉句号、沉默对照、被证实”等抽象解释。

自检不通过必须先重写该条 Prompt，不得继续写入。

## 批量处理

- 先按 `sceneContinuityId` 建立场景连续性 ledger，再按分镜 `index` 顺序逐条处理，不跳行、不合并。
- 同一场景连续多镜必须继承机位组、人物真实站位、道具终态、场景视角和主光方向；动作、景别、当前画面坐标和可见表演逐条独立。
- 参考图编号规则在同一条 Prompt 内稳定；不要跨条强行沿用导致错配。
- 输出内容只用于写入 `prompt` 字段；阻断原因只在阶段完成报告中列出，不写进 Prompt。
