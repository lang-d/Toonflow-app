# 分镜图 Prompt 通用技法

本技法只提供图片 Prompt 生成方法。事实源的读取、写入字段和是否启动图片任务由执行层技能决定。

## 信息来源与优先级

1. `tableRowJson` 是当前镜头人物、动作、位置、朝向、构图、场景和道具的唯一事实来源。
2. `assets` 只提供角色外观、场景结构、道具外观以及可用参考图。
3. `scriptPlan` 只提供“视觉风格与画面基调”、明确的禁用风格词和当前场景已经确定的视觉状态。

低优先级内容不得覆盖高优先级事实。不得从导演规划或资产描述中引入 `tableRowJson` 不存在的人物、动作、物件、剧情或逐镜光影变化。

`dialogue` 和 `soundEffects` 不直接进入图片画面，除非其中已在结构化视觉字段里表现为可见动作、物件或状态。

## 字段映射

| 结构字段 | Prompt 处理 |
|---|---|
| `picture` | 画面主体，必须完整保留所有可见元素和空间关系。 |
| `location` | 环境锚点，结合参考图和风格技法表达。 |
| `shotSize` | 转成镜头构图词；复合景别取首帧起始景别。 |
| `cameraAngle` | 转成视角词；无明确值时不强行添加。 |
| `action` | 识别画面关系，并只保留一个可见静态状态；允许舍弃动作过程。 |
| `characters[].action` | 只提取当前可见姿态、手部状态和交互关系，不追求保留完整动作链。 |
| `characters[].orientation` | 显式写入角色朝向。 |
| `characters[].spatialPosition` | 显式写入角色画面位置。 |
| `visibleEmotion` | 只写可见表演，不写抽象情绪标签。 |
| `requiredAssets` | 生成参考图标注和引用顺序。 |

## 单一静态画面

分镜图是视频的首帧参考，不是整段动作摘要。

- **静态性高于动作语义完整性。** 当完整动作无法在同一时刻成立时，必须舍弃过程、次数、前史和后续结果。
- 静态瞬间：直接按结构化画面生成。
- 连续动作：先选择一个“画面锚点状态”，再只围绕该状态描述画面。
- 画面锚点优先选择最能表达人物关系、核心道具交互或剧情意图的可见瞬间，不机械保留动作第一步。
- 镜头运动：取起始景别和起始构图。
- 转场：只保留开场状态，不生成完整转场过程。
- 不把所有动作都改成“即将发生”的预备态；只有连续动作确实需要首帧化时才处理。
- 一条 Prompt 只能存在一个时间状态，不能同时描述动作的开始、过程和结果。
- 禁止保留动作次数或历史，例如“两次、第二次、再次、反复、重新”。
- 禁止保留时间推进或状态变化，例如“先、然后、随后、逐渐、接着、又、转而、从……到……、最终、紧接着”。
- 禁止把完成态和后续结果串入当前画面，例如“已经、放回、停下、转身离开、没有接、未继续、没再说”。
- 破折号、分号或句号不能用于串联多个先后状态；分句后的所有事实也必须能在同一时刻成立。
- 对“走出并抽出表格放到桌上”这类动作链，只选择其中一个能被单张图片清楚呈现的状态。

## 动态交互冻结

- “递来、接过、放下、转身、走出”等动态动词必须改写为当前可见的空间和姿态。
- “某人递来物件”可冻结为“某人手持物件，手臂从画面一侧伸向另一人”。
- “某人没有接”必须改写为可见状态，例如“双手未伸向物件”，不能只写剧情结果。
- “擦两次围裙后放回身侧”只能选择“手停在围裙上”或“手垂在身侧”其中一个状态。
- 人物姿态与背景物件状态可以并列，但必须能被同一张照片同时拍到，例如人物的手停在围裙上时，背景手机屏幕处于亮起状态。

反例：

```text
她手在围裙上擦了第二次——手停在围裙上，最终放回身侧。她没有接。
```

正例：

```text
林秋岚右手停在围裙上，视线落在陈明远从画面右侧伸来的回执上，双手未伸向回执；背景餐桌上的手机屏幕亮着。
```

## 参考图标注

- 只引用当前静态画面实际使用且真实存在的资产。
- 按 `requiredAssets.order` 建立参考图与 `associateAssetsIds`，从 `@Image1` 开始连续编号。
- `@ImageN` 必须对应 `associateAssetsIds[N - 1]`，编号、数量和顺序必须完全一致。
- Prompt 开头统一写成“参考资产：@Image1 角色A；@Image2 场景B。”
- 正文涉及角色、场景和道具时，可使用名称或对应 `@ImageN` 消除歧义。
- 每个被引用资产必须有唯一编号，不遗漏、不重复、不跳号。
- 禁止引用“位置”“光线”“构图”等非资产内容，禁止虚构不存在的 `@ImageN`。
- 衍生资产使用自身名称和类型；不要回退成父资产名称。

## 人物空间关系

- 每个当前画面可见人物都必须进入 Prompt，不得因其处于背景而遗漏。
- 明确人物位于画面左侧、右侧或中央，以及前景、中景或背景。
- 明确人物以正面、背面或侧面朝向镜头，并写清身体面向方向。
- 明确人物视线方向、当前姿态和与画面有关的手部状态。
- 多人物画面必须写清人物之间的左右、前后、遮挡和面对关系。
- 如果结构化字段只有“厨房台面旁”等场景位置，应结合 `picture` 中已有空间关系表达，不得凭空发明精确站位。

## 可见状态

- `visibleEmotion` 只转换成肉眼可见的表情、视线、姿态、呼吸或手部状态。
- 禁止写“代表、体现、说明、意味着、象征、仿佛、内心、注意力开始分裂”等心理解释和叙事判断。
- 抽象描述没有可见依据时直接省略，不自行创造表演细节。
- 氛围必须落实为结构化事实或参考图中已存在的光线、色彩、天气、空间状态；禁止使用空泛情绪氛围词替代画面事实。

## 输出语言与结构

- 除 `@ImageN` 外全部使用中文，不附加英文翻译、英文参考说明、XML、Markdown 或负向词块。
- 使用紧凑的三段式纯文本：
  1. `参考资产：` 按顺序列出实际使用的 `@ImageN`；无参考图时省略此段。
  2. `静态画面：` 写景别、场景、人物空间关系、朝向、姿态、可见物件和单一动作状态。
  3. `视觉风格：` 只写 `scriptPlan` 已确定的短视觉原则，最多一句；没有明确原则时省略。
- 画面段优先级最高，风格描述不得覆盖、替换或挤掉具体画面事实。

示例：

```text
参考资产：@Image1 林秋岚；@Image2 陈家厨房。
静态画面：中景。林秋岚位于画面左侧中景，背对镜头，身体面向右侧灶台，视线落在旋钮上，右手停在灶台旋钮上；陈家厨房位于背景。
视觉风格：自然室内光，生活化暖色，低戏剧化阴影。
```

## 忠实性校验

生成每条 Prompt 后逐项自检：

- `picture` 中所有可见主体、物件、空间层次是否保留。
- `location` 是否与结构化字段一致。
- `shotSize` 是否匹配。
- 是否选择了最能表达当前人物关系或核心交互的画面锚点。
- 角色朝向是否来自 `characters[].orientation`。
- 角色位置是否来自 `characters[].spatialPosition`。
- `visibleEmotion` 是否转成可见表演，而非抽象词。
- 是否引入了结构化分镜没有的角色、道具、剧情、场景状态或动作。
- 是否遗漏了 `requiredAssets` 中画面可见的资产。
- 是否把动作链压缩成单一静态状态。
- 是否删除了动作次数、前史、完成态和后续结果。
- 所有分句中的人物姿态与物件状态是否能在同一时刻成立。
- 是否写清每个可见人物的位置、正背侧面、身体朝向和视线。
- `@ImageN` 是否与 `associateAssetsIds` 数量、顺序完全一致。
- 是否出现中英文混排、心理解释或时间推进词。

校验不通过必须修正，不得继续写入。

## 人物连续性

- 同一角色跨分镜保持服装、发型、面部特征和体型一致。
- 同一场景内人物左右关系、前后层次和朝向连续。
- 朝向变化必须对应结构化动作中的转身、转头、走位等可见动作。
- 多角色画面优先写清“谁在画面左/右/前/后、面向谁、注视哪里”。

## 视觉状态与光影色调

- 不凭空新增光线方向、色温、明暗关系、色彩风格。
- 只能来自 `scriptPlan`、场景资产状态、结构化分镜明确事实或参考图。
- 有参考图时，以参考图中的环境、光线和色彩为准。
- 如果结构化分镜只写普通室内，不得自行扩写成夜景、雨景、逆光、高对比等状态。

## 画质与文字规则

- 只保留功能性要求：主体清晰、人物和物件可辨认。
- 禁止自动加入“真人摄影、电影级、4K、8K、极致细节、纹理超清晰、胶片颗粒、超现实主义纪实、发丝根根分明”等质量或摄影填充词。
- 禁止画外字幕、水印、标题卡、界面文字。
- 如果画面内自然存在文字道具，只在结构化分镜明确提及时描述其存在，不生成额外文字内容。
- 不输出独立负向词块，不从画风手册复制固定画质锁定词。

## 批量处理

- 按分镜 `index` 顺序逐条处理，不跳行、不合并。
- 同一场景连续多镜可以复用场景质感，但动作、景别、朝向、空间位置和可见表演必须逐条独立。
- 参考图编号规则在同一条 Prompt 内稳定；不要跨条强行沿用导致错配。
- 输出内容只用于写入 `prompt` 字段，不附加资产汇总、台词备注、音效备注或校验报告。
