# 分镜表设计通用技法

本技法只提供通用分镜设计方法和质量校验细则。事实写入方式、工具调用和阶段边界由执行层技能决定。题材拆镜、题材化对话反应、节奏钩子由当前 `director_storyboard_table_narrative` 补充，但不得覆盖本技法中的字段、资产、时长、`soundEffects`、分组和工具契约。

本技法不得写死 Social realist、悬疑、甜宠、喜剧等任何固定题材规则；题材专属方法只能出现在被当前项目选择的导演叙事手册中。

## 字段口径

本技法统一使用结构化分镜字段：

| 创作含义 | 结构字段 |
|---|---|
| 画面描述 | `picture` |
| 场景 | `location` |
| 时长 | `durationSec` |
| 景别 | `shotSize` |
| 运镜 | `cameraMove` |
| 全局动作概述 | `action` |
| 角色动作 | `characters[].action` |
| 朝向 | `characters[].orientation` |
| 空间关系 | `characters[].spatialPosition` |
| 可见情绪 | `visibleEmotion` |
| 台词 | `dialogue` |
| 音效 | `soundEffects` |
| 关联资产 | `requiredAssets` |

## 画面事实边界

分镜表是可拍摄镜头表，不是角色设定复述、场景设定复述或图片 prompt。每条 `picture` 优先写当前镜头的构图、站位、视线、遮挡、动作、可见状态和叙事信息。

## 生成前内部草算与提交前自检

在输出任一 `StoryboardTableRow` 前，先在内部完成以下草算；这些草算不写进字段，也不需要展示给用户：

1. 资产锚定：区分已由 `requiredAssets` 承担的稳定设定，和本镜必须新写的临时状态、动作、遮挡或空间关系。
2. 场景镜头 ledger：从导演规划提取人物站位与视轴图、轴线、机位组、轴线侧、已有覆盖资产、人物真实站位和道具终态；图中的 `[事实]` 才是可继承空间事实，`[规划]` 是导演选择，`[缺口]` 不是可用覆盖；初态和关键变位不是画面坐标。
3. 台词时长草算：按当前语气、停顿、表演出口和动作承接判断建议整数秒，不用镜头数量或视频分组上限替代台词时长。
4. 单镜自检：确认本镜只有一个机位和一个可拍摄时刻，且相邻镜头新增了信息、动作、反应、关系距离或空间后果。

提交前再独立复核一次：已引用资产的稳定外观是否被重复写入，`visibleEmotion` 是否变成心理解释，机位签名是否来自导演规划，台词和动作是否确实装得进建议时长。发现疑点时由模型自行调整行内容，不把草算过程写进分镜表。

### 剧情事实 ledger

拆镜前按剧本原始顺序建立剧情事实清单，每项使用稳定 `eventId`，记录事件、关键动作、全部原文台词和因果职责。随后把每条预演镜头关联到一个或多个 `eventId`，并在正式写表前反向核对：

- 剧本中的关键台词、动作、事件顺序和因果关系必须逐项覆盖。
- 不得省略建立人物动机、改变关系或触发决定的关键台词。
- 不得为了分组、时长或镜头方便提前、延后或倒置事件。
- 合并镜头只能改变呈现方式，不能改变故事发生顺序。
- 若一项事件没有镜头承接，或一个镜头无法指出对应事件，先修正预演，不得进入正式写表。

### 情绪曲线 ledger

按当前剧情实际标记建立关系与目标、压力或诚意升级、犹豫与不可逆转折、决定执行、现实后果和结尾落点。题材手册决定具体表达偏好，本通用技法只要求曲线完整：

- 信息交代可以紧凑，对话和动作链必须完整。
- 核心决定减少切换，让表演在一个镜头内成立。
- 行为结果落下后可以停顿，最长停留优先给真正的情绪落点。
- 禁止全片平均使用相同的两三秒节奏，也不得用空镜或重复反应机械补总时长。

资产已通过 `requiredAssets` 锚定时，不得在 `picture`、`action` 或 `visibleEmotion` 中复述该资产的稳定设定：

- 角色稳定外观：年龄、脸型、五官评价、固定发型、固定服装、常态妆造、身材设定、基础气质。
- 场景稳定设定：固定装修、固定陈设、空间风格、常态光影和常态色彩。
- 道具稳定设定：固定材质、基础造型、常态纹样和长期属性。

允许写入的是当前镜头新增的可拍事实：

- 站位、构图层次、前后景遮挡、视线方向、动作节点、手部行为、姿态变化。
- 剧情导致的临时状态，例如湿发、哭后眼红、衣服沾灰、手机屏幕亮起、桌面被清空。
- 导演规划或已存在衍生资产明确要求的当前时间、天气、损坏、换装、病后、收摊、下班等状态。

若已有匹配衍生资产，使用衍生资产 ID 承接外观/状态变化，不再长篇描述外观。若剧情需要某状态但 assets 中没有匹配衍生资产，只能在 `picture` 中短写当前镜头必要事实，并把它视为上游衍生覆盖缺口，不得虚构资产 ID。

## 拆镜原则

- 新起分镜：地点切换、时间跳跃、镜头主体切换、景别明显变化、重要动作节点、关键情绪转折、信息揭示方式变化。
- 不必新起分镜：同画面内连续短对话、同一动作链的微表情变化、可由一次运镜完成的信息递进。
- 每条分镜应表达一个明确可拍摄画面，不遗漏剧本内容，也不新增剧本不存在的情节。
- 定场镜头每个新场景最多 1–2 条；能一镜完成定场和主体引入时不要拆成碎片。
- 完成后做镜头合并自检：纯装饰、同空间重复局部、无新增信息的相邻镜头应合并。
- 拆镜优先围绕剧情信息、动作节点、关系距离和情绪转折；不要为了“氛围”“高级感”拆装饰性碎镜头。

## 镜头经济

每条分镜必须至少承担以下一种新增功能：

- 新信息：观众获得新的剧情事实、证据、对象或空间关系。
- 新动作：人物或物件发生可见动作节点。
- 新反应：角色对台词、事实、动作或环境变化产生可见反应。
- 新关系距离：人物间站位、视线、遮挡、靠近/后退或权力位置发生变化。
- 新空间后果：门关上、座位空出、桌面清空、物件被拿走、队伍停住等现实变化。

相邻镜头若同时满足“同空间、同主体、同景别、同信息、无新动作/反应”，必须合并。过渡镜头默认短，只在承担场景转换、情绪落点、信息延迟或动作承接时保留；不得为了氛围插入空镜。

- 同一动作的准备、发生、停顿和反应不得默认各拆一镜；先判断能否由一个完整表演镜头承载。
- 微表情只有改变观众对人物选择或关系的理解时才获得独立镜头。
- 核心转折优先使用较少镜头和完整表演，不得用连续碎特写稀释情绪。
- 结尾优先减少切换并延长最终落点，不得用多个道具特写反复解释同一信息。

## 单镜纯度

- 每条分镜只能使用一个主机位，描述一个连续时刻或同机位下可完成的连续动作链。
- `picture` 禁止出现“然后切到”“再切到”“转而切到另一机位”等把剪辑序列塞进单条分镜的表达。
- 蒙太奇必须拆为多条相邻分镜，用相同 `beatId/groupKey` 表达组合关系。
- 同机位连续动作可以保留，但总时长必须容纳动作，且人物空间关系和镜头朝向不发生隐性跳变。

## 导演规划对齐

写入前先从 `scriptPlan` 建立参考表：

- 段落锚点：段落编号、对应场次、情绪浓度、节奏、段落过渡方式。
- 场次执行映射：出场资产、表演出口、空间关系、人物站位与视轴图、镜头距离策略、连续性锚点、核心环境音。
- 轴线与机位参考：从导演规划的空间账本、人物站位与视轴图和⑤分场景执行规划提取 `场景/初态或关键变位/活跃轴线/机位组与半区/叙事功能/覆盖资产状态`。

### 场景镜头 ledger

开始逐条写分镜前，必须为每个主要 `sceneContinuityId` 建立场景镜头 ledger：

- 场景与时间：`location`、`timeOfDay`、场景状态、天气/时段/收摊/损坏等衍生状态。
- 空间账本：活跃轴线、守轴范围、可验证的机位半区与镜头朝向、可用机位组、转轴条件，以及每项覆盖资产的“已验证可用 / 资产缺口”状态。分析中的“可推断但需确认”不得写入可用 ledger。
- 站位转换：从真实站位图推导当前机位下的画面左右、前后景和遮挡关系；画面左右不是上游俯视图坐标。
- 站位与道具：角色初始位置、手持/佩戴/操作道具、关键物件位置。
- 可用插镜：证据、手部、物件、空间后果、环境反应等可插入镜头，并标明叙事功能。

每条分镜必须从 ledger 的既有轴线、机位半区和机位组中选择。确实需要导演规划未覆盖的机位角度时，不得把父场景自动当成覆盖；只有标为 `已验证可用` 的现有资产可证明支持该必要空间事实时才能引用，否则保留“场景视角资产缺口”，等待上游规划或衍生阶段处理。不得把导演图中的 `[规划]` 或 `[缺口]` 当成参考图已证实的空间事实。

### 分镜面板交接契约

轴线、机位和站位结论不能只存在于生成过程的内部 ledger，必须写入 `StoryboardTableRow` 的现有字段，供分镜面板直接继承：

- `cameraAngle` 使用标准机位签名：`轴线｜机位组｜轴线侧/半区｜人物视角｜镜头朝向`。机位签名既要包含导演规划中的标识，也要包含可直接理解的半区和朝向描述；不得只写“侧面”“正面”“过肩”“角色侧”或“正反打”等模糊值。
- 示例：`主对抗轴A｜A2｜轴线同侧半区｜角色A侧3/4｜朝已确认互动对象`。
- `characters[].spatialPosition` 同时写画面位置和真实站位，例如：`画面右侧中景；真实站位：已确认锚点旁`。真实站位必须优先继承导演规划站位图；画面位置只在选定当前机位后再转换，绝不可把俯视图中的左右位置机械抄成屏幕左右。
- `characters[].orientation` 分开写身体朝向、脸部朝向和面对对象；`posture` 明确站立、坐着、蹲下、倚靠或俯身；`gaze` 与 `handAction` 分别写当前视线对象和手部终态。
- `requiredAssets` 中的场景资产必须优先使用与当前机位签名、时间、天气和空间状态匹配的已有衍生资产。存在匹配衍生时不得只写父场景资产。
- 若缺少匹配机位资产，`picture` 只保留当前镜头必要空间事实，并把“场景视角资产缺口”留给分镜面板阻断或上游补资产；不得假设图片模型能从父场景主视图可靠反推反向空间。

分镜面板只负责把这些已落库事实编译成单张静态图，不负责重新选择轴线、机位或人物真实站位。

### 机位串联

机位不是逐条随机选择，而是按连续镜头语法串联：

- 新场景先建立空间与主轴线，定场和主体引入可一镜完成时不拆两镜。
- 对话/对峙段落按“主说话者、听者反应、关系空间、必要过肩/侧面”组织，不做机械正反打流水账。
- 信息/证据段落按“物件或屏幕可读 → 人物反应 → 行动后果”组织，复杂信息不要拉长单个读屏镜头。
- 动作段落按“动作起点 → 动作执行 → 动作结果”组织，能在同一镜头清楚完成的动作链不要拆碎。
- 轴线切换必须由走位、转身、进入/离开、递交物件、视线被道具接管等可见动作承接。
- 插镜必须服务信息、情绪或动作承接；纯氛围空镜、无新增信息的局部特写应删除或合并。
- 每个机位必须遵守 ledger 已定义的机位半区和人物画面关系；机位名称相似不代表空间连续。正反打默认保持同一轴线侧，跨轴只能通过中性机位、人物走位、摄影机运动或重新建立空间后发生。
- `transitionFromPrevious` 写真实承接方式：动作匹配、视线匹配、声音桥、空间重建或有明确意图的硬切；不得把“硬切”当作所有镜头的默认占位。

逐条分镜检查：

- `shotSize` 必须落实导演规划中的距离感和镜头意图。
- `cameraMove` 必须呼应镜头意图，不得与情绪方向相反。
- `cameraAngle`、角色朝向和画面左右关系必须服从导演规划中的轴线设置；同一对话/对峙场景默认遵守 180 度视轴。
- 当前镜头需要反向、过肩、侧面、道具插入、高位/俯视或钩子角度时，必须优先使用导演规划列出的机位组和覆盖资产。
- 如果分镜确实需要导演规划未覆盖的机位角度，不得自行发明新的场景衍生资产，也不得用父场景假定未知反向空间；把“机位覆盖缺口”留给上游规划/衍生阶段修正。
- 段落切换点必须设置合理转场或过渡镜头。
- 高节奏段落镜头更密，低节奏段落允许更稳的构图和更长停留。
- `soundEffects` 只承载画内环境音和动作音，优先来自导演规划标注的核心声源。
- 导演规划的表演出口必须落到 `characters[].action`、`visibleEmotion`、`gaze`、`handAction`、`movement` 等结构字段，不要只写进 `picture`。
- 供分镜面板使用的站坐、身体朝向、脸部朝向、视线、手部终态和场景角度资产必须落入对应结构字段，不得依赖 `picture` 中的长句隐含表达。

## 视觉连续性

- 相邻分镜的动作终态和下一镜起态必须衔接。
- 同一场景内角色站位、注视方向和互动对象要稳定；变化时必须在 `characters[].action` 写出转身、转头、走位等衔接动作。导演规划标记为关键变位时，必须从该变位动作开始更新真实站位、轴线侧和画面关系，不得在未定义变位的镜头中无故跳变。
- 遵守 180 度视轴：对话或对峙双方的画面左右关系不能无理由跳轴。
- 若导演规划定义了主对抗轴线、入口/出口轴线或道具轴线，分镜必须说明本镜头属于哪条轴线或为何切换轴线；轴线切换需要由走位、转身、进入/离开、道具接管视线等动作承接。
- 景别切换应有叙事理由；连续多个同景别镜头会造成疲劳，除非表达故意停滞。
- 单镜不要塞入过多动作：短镜头承载 1 个动作或 1 句短台词；长镜头也要控制在清晰动作链内。
- 每条分镜前后保留自然进入和收束，不把关键动作或台词压在边缘。

### 站位与连续性 ledger

同一 `sceneContinuityId` 下必须持续追踪：

- 每个角色的 `spatialPosition`、`orientation`、`gaze`、互动对象。
- 手持、佩戴、触碰、遮挡或操作的道具状态。
- 上一镜动作终态、当前镜动作起态、下一镜需要承接的动作。
- 场景状态和关键物件位置，例如门是否开着、文件是否已拿起、手机是否亮屏、座位是否空出。

下一镜必须承接上一镜终态。若站位、朝向、视线对象或道具状态发生变化，必须在 `characters[].action`、`movement`、`handAction` 或 `picture` 中写出可见承接动作。

## 朝向与空间关系

`characters[].orientation` 必须写清角色面部或身体朝向：

- 单角色可写“面朝右”“3/4正面朝左”“背对镜头”等。
- 多角色按画面出现顺序分别写入各自对象。
- 空镜或纯物件镜头可不写角色项。
- 角色朝向改变时，必须有可见动作承接。

`characters[].spatialPosition` 必须写清角色在画面中的稳定位置：

- 推荐位置词：左前、中前、右前、左中、中中、右中、左后、中后、右后。
- 多角色场景必须体现相对关系。
- 同一场景同一组角色的位置应稳定；走位时要同步更新位置和动作。

## 动作与可见情绪

- `action` 是整条分镜的全局动作概述。
- `characters[].action` 写角色具体动作链，避免只写静态结果。
- `visibleEmotion` 必须落到当前画面可拍摄表现：眼神、呼吸、姿态、手部动作、步伐、停顿、语气出口、面部肌肉。
- 禁止只写抽象标签，例如“悲伤”“坚定”“压迫”“冷傲”。应写成“嘴角压平、视线下移、手指攥紧、呼吸变浅”等可见事实。
- `visibleEmotion` 只概括本镜头此刻的可见状态，不写剧情解释、关系判断或情绪变化过程。
- 禁止使用“从……到……”“形成反差”“被戳中但不说”“内心……”“情绪转换”等解释性表达。
- 如果需要表达情绪转折，把转折动作拆到 `action` 或 `characters[].action`；如果需要表达人物关系变化，把它放入 `picture/action` 的画面事实中，不放进 `visibleEmotion`。
- 不合格：`安静——从嘈杂到空旷的情绪转换`；合格：`脚步放慢，肩背松垮，视线落在空摊位上`。
- 不合格：`王姨温和——和之前的大嗓门形成反差`；合格：`王姨眉眼放软，身体前倾，语速放慢`。

## 台词与时长

- `dialogue[].text` 必须保持剧本原文，不改写、不意译、不漏句。
- 一条分镜内不要塞入多轮长对白；需要时拆镜。
- `durationSec` 必须容纳台词和可见表演。
- `durationSec` 必须是整数秒，禁止小数。
- 由模型结合人物语气、完整台词、自然停顿、动作和反应语义估算，不使用后端固定语速公式。
- 台词与复杂动作共存时，优先延长镜头或在自然落点合理拆镜，不得压缩、改写或删除对白。
- 一秒镜头只承载真正瞬时的信息或动作，不承载完整台词、犹豫、停顿和人物反应。
- 无台词镜头默认 2–4 秒；转场、空镜、物件插镜超过 6 秒时，必须有新的动作、信息或空间变化支撑。
- 全部镜头完成后核对剧本目标总时长；总时长不足或超出时先检查遗漏、重复和表演空间，不得机械平摊秒数。

## 资产引用

- 画面中可辨识的角色、场景、道具、片段都必须写入 `requiredAssets`。
- `assetId` 必须是真实资产 ID，不得编造。
- 当前画面需要某个衍生状态时，优先引用匹配衍生资产；没有匹配衍生状态时才引用主资产。
- 同一父资产在单条分镜中不要主资产与衍生资产重复引用，除非画面确实同时出现两个独立可见对象。
- `requiredAssets.order` 从 0 开始，表示稳定参考顺序；同类镜头尽量保持顺序一致。
- 剧本出现但资产库不存在的对象可以写进画面事实，但不能编造 `assetId`。

### 资产引用四步检查

每条分镜提交前按以下顺序检查 `requiredAssets`：

1. 主体：镜头主要拍谁或什么，主体资产必须引用。
2. 场景：画面所在空间是否可辨识；可辨识则引用场景资产或匹配场景衍生。
3. 背景：背景里是否有可辨识角色、场景区域、道具或衍生状态；可辨识则引用。
4. 交互：角色手持、佩戴、触碰、遮挡、操作的道具或角色是否可辨识；可辨识则引用。

引用边界：

- 角色特写但背景能看出菜市场、学校走廊、客厅等场景时，场景资产也要进入 `requiredAssets`。
- 拍道具特写但道具由某角色佩戴、手持或操作时，角色资产也要进入 `requiredAssets`。
- 拍 A 的单人近景，但 B 的肩膀、背影、手、虚化轮廓可辨识时，B 也要进入 `requiredAssets`。
- 完全不可辨识的模糊路人、远处杂物、抽象背景纹理不强制引用。
- assets 中不存在的对象不进入 `requiredAssets`，也不能虚构 ID。

### 衍生资产选择

- 夜景、雨天、收摊、破损、换装、哭后、病后、脏污、激活、维修后等状态若已有匹配衍生资产，必须引用衍生资产。
- 场景衍生资产选择必须匹配导演规划中的机位/轴线/时间/天气/空间状态；例如反向视角、入口看向室内、雨夜、收摊后等状态已有衍生时优先引用对应衍生。
- 无匹配衍生资产时，只能在父资产足以支持当前镜头必要空间事实的情况下回退父资产；否则保留资产缺口，并在 `picture` 中仅写剧本已确认的状态。
- 不要同一父资产在同一条分镜中同时引用父资产和其匹配衍生资产。

## 声音与后期音乐

- `soundEffects` 只写画内真实声源：环境音、动作音、拟音。
- 不把 BGM、旋律、乐器氛围写入 `soundEffects`。
- 如果需要后期音乐，只能作为分镜组级后期建议，不进入分镜事实字段。

## 视觉状态与光影色调

- 不逐镜凭空添加光线方向、色温、明暗关系或色彩风格。
- 视觉状态只能来自导演规划、场景资产状态、结构化分镜明确事实或参考图。
- 夜景、雨天、火光、破坏等状态应通过 `location`、`picture`、场景衍生资产或导演规划明确表达。
- 不得与参考图中的环境、光线和色彩事实冲突。

## 转场

- 同场戏内默认硬切，除非导演规划指定特殊过渡。
- 跨场景可插入 1 条短过渡镜头，内容必须与前后场景氛围相关。
- 大段落切换可用淡入淡出、空镜或物件特写表达，但不得使用无叙事意义的花哨转场。
- `transitionFromPrevious` 只描述与上一镜的衔接方式，不承载新剧情。

## 分镜组与后期 BGM 建议

### 同一 Agent 内存预演优先

- 分镜表 Agent 在同一上下文中先调用 `prepare_storyboard_table` 固化镜头顺序、建议时长和组边界，再开始 generation；不得启动另一个模型重复规划，也不得重新按索引或秒数机械分组。
- 先按叙事、表演、台词、情绪和镜头语法拆镜，再只在已有镜头之间安排视频生成组。生成组不是场次，也不是完整戏剧段落；同一场景、同一事件可以跨多个生成组。
- 组边界优先落在台词落点后的听者反应、动作终态、道具插镜、视线转移、人物进出、轴线切换或空间后果之后。
- 禁止在一句台词、未完成动作、不可分割表演过程或单条镜头中间切组。禁止为了模型时长删减台词、压缩表演、改变镜头顺序或增加填充空镜。
- 若写表时发现真实叙事必须改变镜头数量、顺序或分组，停止当前追加，重新提交内存预演并重新 begin；不得在原 generation 中悄悄制造行数或分组漂移。
- 单个不可拆长镜头超过当前动态模型能力时，必须等待用户选择更换模型或明确授权重新设计镜头；不默认建议或执行后期伪长镜头拼接。

- 分镜组是一次视频生成单元，不是场次。
- 同一分镜组只表达一个连续事件目标或戏剧功能。
- 跨场景、跨时间、跨事件目标、跨戏剧功能必须新建分镜组。
- 单组总时长必须服从项目默认视频模型能力；不要写死固定秒数。
- 分镜组可生成后期 BGM 建议，包括 mood、intensity、tempo、entryPoint、exitPoint、syncPoints、avoid、postNote。
- BGM 建议只供后期制作参考，不进入分镜事实字段。
