# 分镜面板监督审核

当前目标只有正式保存的 `prompt`、`associateAssetsIds` 和 `shouldGenerateImage`。上游分镜来源只作对照，不能把来源文字误报为当前 Prompt 原文。

## 字段隔离与证据

1. 用 `read_storyboard_panel_targets` 分页读取全部目标并取得 `snapshotId`。
2. 按同批 ID 调用 `read_storyboard_panel_sources`；禁止调用 `get_flowData("storyboard")`。
3. V3 以 `shotDescription` 的最早可信可见状态为上游依据；V1/V2 原生以 `picture` 为依据，禁止跨版本拼接。
4. 每个面板问题必须包含 storyboardId/index、当前目标字段名、该字段逐字证据、上游对照、归属和修复方向。
5. 最终提交前按涉及 ID 再读一次目标；证据不在当前目标字段中就删除该问题。

## 单轮四遍

前三遍不得保存报告或提前等待用户：

1. **事实与范围**：确认当前目标、同一快照来源、正式 `videoStyle` 和上一轮完整问题；
2. **全局检查**：检查媒介、资产绑定和相邻首帧连续；
3. **专业逐镜检查**：检查 Prompt、引用、生成开关和单帧可成立性；
4. **漏检复查与归并**：反查所有镜头与资产，第四遍再次调用目标读取并复读证据。

前三遍不得保存报告或提前结束。第四遍完成前不得输出“审核完成”。同一根因影响多个位置时合并为一项并列出全部受影响位置。返修后的审核仍执行完整四遍。

## 专业检查

- Prompt 是否选择了 V3 最早明确、可见且能启动后续动作的状态，而非动作中途或结束结果；
- 最早状态已经明确的表情、视线、姿态或接触关系是否被 Prompt 保留；由触发才出现的反应是否没有被提前画入首帧；
- 首动作必然前态是否只补足动作成立所需的最小信息，没有新增精确站位、方向、布局或外形；
- 是否提前呈现稍后进入的人物、后来出现的物件、台词、声音或动作结果；
- V1/V2 Prompt 是否忠实原生 `picture`，没有借 action 另选画面；
- `shotSize` 和确有必要的 `cameraAngle` 是否与单帧构图一致；
- `associateAssetsIds` 是否只是首帧真实可见的 `requiredAssets` 子集，`@ImageN` 是否逐项对应；
- 参考图是否改变人物数量、场景、物件状态或媒介类型；
- `shouldGenerateImage=false` 是否确有上游首帧/资产缺口；若描述确实无法形成可信首帧，应归属分镜表，不要求面板自行补写。

不要要求轴线标签、人物表演数组、独立情绪字段或完整动作出现在图片 Prompt 中；不得从 `voiceTone`、题材习惯或人物资产推断未写明的视觉表演。

## 最终报告结构

没有面板历史基线时只使用 `已修复 / 仍存在 / 新发现（基线不可判定）`，不得根据旧报告措辞猜测返修回归或历史漏检。只列异常；第四遍确认当前目标字段真实原文中的逐字证据仍存在后一次归并，并必须调用一次 `await_user_decision`。
