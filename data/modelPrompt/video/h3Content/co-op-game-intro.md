# H3 single-shot expression skill: co-op game opening

## Scope and fact inheritance

Use this layer only when the current storyboard and references explicitly establish a two-player/co-operative game opening, its two subjects, game title or supplied UI/copy, and a confirmed interaction. It is not the official confirmation-image workflow, and it must not create a menu framework, player cards, names, buttons, icons, title, palette, game rules, score, mission, enemy, or HUD that the Toonflow facts do not already provide.

Keep each supplied subject's identity, screen position, facing direction, established visual style, UI copy, and interaction result intact. A reference picture supplies only its assigned role. Do not infer a player's identity or a game's rules from reference order, asset names, or genre.

## Game-opening composition grammar

Organize the one shot around the confirmed shared focal event: two players entering relation, an existing selection/confirmation, an existing UI response, or a supplied title reveal. Preserve a verified UI hierarchy: UI may frame or support the interaction but must not block the fact-supported subject. Keep supplied layout, palette, typography, and screen state stable; do not replace it with an arbitrary commercial game-menu design.

If two subjects act, make the co-operative relationship spatially intelligible—who initiates, who responds, what shared object/UI state changes, and the confirmed result. Use camera movement only to clarify the existing interaction or confirmed composition. Never manufacture competitive action, combat, controller input, celebration, or a new gameplay event.

## Timeline compilation

Write a continuous sequence: existing opening layout and player/UI state -> confirmed co-operative action or interface event -> established final shared state. Maintain player identity and UI continuity through the whole supplied duration. If text appears, reproduce only exact supplied wording at the supplied moment; do not create a title card or menu copy merely because the type is selected.

Keep dialogue and diegetic sound in order. UI sounds, game stingers, crowd reactions, and music are included only when explicitly supplied as diegetic facts; otherwise omit them. Never add BGM or a game soundtrack.

## Missing-fact policy and boundaries

If there are not two evidenced subjects, no supplied UI/copy, or no verified co-operative event, compile the original shot without inventing game-opening elements. Do not create HUD, buttons, icons, controls, scores, missions, enemies, player names, rules, voice lines, or music.

Do not override the formal `videoStyle`, storyboard chronology and duration, keyframe/reference roles, media labels, dialogue, visible text, diegetic sound, or the no-BGM rule.

## Final check

The final prompt must preserve the confirmed two-subject/UI relationship and its actual result. It must never turn a generic character shot into an unsupported game menu.
